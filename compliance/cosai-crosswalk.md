# CoSAI Risk Map to FedRAMP CR-26 Authoritative Crosswalk

**Dataset Provenance:** FedRAMP Consolidated Rules for 2026 (`2026.11.02.01`, updated `2026-11-02`) × Coalition for Secure AI (CoSAI) Risk Map (`42` Components, `36` Risks, `37` Controls, `10` Personas, `6` External Frameworks)  
**Analysis Date:** `2026-11-19`  
**Approved Scope:** FedRAMP **Class C** (`20x` + `Rev5`) and **Class D** (`Rev5` + `20x`-ready for `2027`) across `runtime-cso` and `internal-devsecops` agent profiles  
**Machine-Readable Companion:** [`cosai-crosswalk.json`](cosai-crosswalk.json) | **Engineering Specification:** [`../specifications.md`](../specifications.md) | **Rule Catalog:** [`../relevant-rulesets.md`](../relevant-rulesets.md)

> [!IMPORTANT]
> **Zero-Invention Regulatory Discipline:** In FedRAMP CR-26 version `2026.11.02.01`, five 20x Key Security Indicators (`KSI-CNA-EIS`, `KSI-MLA-ALA`, `KSI-SVC-PRR`, `KSI-SVC-RUD`, `KSI-SVC-VCM`) and persistent machine-verification rule `VDR-TFR-MVX` define variants through Class C (`b`/`c` or `a`/`b`/`c`) and omit `varies_by_class.d` pending the 2027 20x Phase 4 Pilot (as noted in `SDR-CSX-KMT`). Wherever those IDs appear below, Class D relies on common `FRR` rules and `Rev5` High `CTL` entries rather than invented 20x Class D statements. Remember also that `KSI` entries carry capability statements without RFC-2119 normative force (`MUST`/`SHOULD`/`MAY`).

## 2. Class C vs. Class D Enforcement Elevation Summary

| Security Domain | CR-26 Rule / Control IDs | Class C (`20x` + `Rev5`) | Class D (`Rev5` + `20x`-Ready) | `agent-manifest.json` Gate |
|---|---|---|---|---|
| **Cryptographic Modules** | `CMU-CSO-UVM`, `CMU-CSO-CMD`, `CTL.SC.SC-13` | SHOULD use active CMVP FIPS-validated modules (SDR rationale required if non-validated). | MUST use active CMVP FIPS-validated cryptographic modules across all federal data protection boundaries. | `cryptography.fips_140_3_validated_modules` |
| **Per-Service Certification Materials** | `CDS-CSO-PSM` | MAY supply per-service FedRAMP Certification materials. | MUST supply per-service FedRAMP Certification materials. | `lifecycle.per_service_certification_artifacts` |
| **Digital Identity & Encrypted Assertions** | `CTL.IA.IA-05` | NIST Digital Identity Guidelines IAL2/AAL2/FAL2 + XML-Encryption (SAML) or JWE (OIDC) assertions. | NIST Digital Identity Guidelines IAL3/AAL3/FAL3 + XML-Encryption (SAML) or JWE (OIDC) assertions. | `identity_access.digital_identity_level` |
| **Data, Inference & Service Residency** | `CTL.SA.SA-09-05` | Document external service locations for all federal customer data. | All information processing, federal customer data, and system services MUST remain within U.S./U.S. Territories or geographic locations under U.S. jurisdiction. | `model_serving.us_jurisdiction_only` |
| **Vulnerability Evaluation & Incident Escalation** | `VER-TFR-EVU`, `VER-TFR-NRI`, `VDR-TFR-PVR` | Evaluate within <= 5 days (VER-TFR-EVU); PAIN=5 IRV+LEV mitigated within 2 days (VDR-TFR-PVR); non-IRV PAIN=5 LEV incident treatment is MAY (VER-TFR-NRI). | Evaluate within <= 2 days (VER-TFR-EVU); PAIN=5 IRV+LEV mitigated within 12 hours (VDR-TFR-PVR); non-IRV PAIN=5 LEV incident treatment elevates to SHOULD (VER-TFR-NRI). | `lifecycle.vdr_triage_sla_days` |

**Verification Method Legend:**
- `automated-cli`: Mechanically enforced pre-commit and in CI via `tools/validate_manifest.py`, `tools/audit_agent_repo.py`, and `tools/check_neutrality.py`.
- `hybrid-cli-and-ivv`: Structural manifest invariant checked automatically via CLI tools, paired with runtime/configuration evidence inspected during Independent Verification & Validation (`IVV-CSO-SEI`, `IVV-CSO-SEE`).
- `procedural-ivv`: Verified via Security Decision Records (`SDR`), Secure Configuration Guidance (`SCG`), Trust Center packages (`CDS`), and annual `IVV` assessment.
