## 4. Six Cross-Cutting Architectural Patterns Observed Across Real CSOs

### (a) Deployment Model: GovCloud vs. Public / Hybrid Cloud
- **Observed Data:** Across `data.json`, **69.4%** of High (Class D) offerings run on Government Community Cloud vs. **21.8%** Public Cloud and **8.9%** Hybrid. Conversely, among the `141` 20x CSOs in `fedramp-frc-cso-pkg.json`, **67.4%** run on Public Cloud and **29.1%** on Government-Only / Government Community Cloud (rising rapidly for AI/security CSOs).
- **Inference for `fedramp-agent`:**
  - **Class C (`20x` or `Rev5`):** Commercial Public Cloud with FedRAMP-certified IaaS/PaaS (`F1209051525` Azure Commercial, `FR1805751477` GCP Assured Workloads, `AGENCYAMAZONEW` AWS US East/West) is the dominant, FedRAMP-encouraged deployment model—provided U.S. Data Zone / Assured Workloads boundaries and strict tenant isolation are enforced.
  - **Class D (`Rev5` & 2027 `20x`):** Although homogeneous Public Cloud is possible at hyperscale (`FR2000863987A` Cloudflare, `FR2315464863` Palantir PFCS-SS), the overwhelming majority of Class D CSOs (and dedicated Class D editions from Dynatrace, New Relic, Databricks, Snowflake, stackArmor) deploy into **Government Community Cloud / Government-Only Cloud** (`aws-us-gov`, Azure Gov, Assured Workloads) to satisfy `CTL.SA.SA-09-05` (U.S./U.S. Territories/U.S. jurisdiction), `CMU-CSO-UVM` (mandatory FIPS CMVP), and U.S.-person operations expectations (`CTL.MA.MA-05`, `CTL.PS.PS-07`).

### (b) Certified vs. Non-Certified TPIRs for LLM Inference & Observability
- **Observed Data:**
  - **Certified Inference TPIRs:** Leading 20x/Class D AI CSOs route prompts exclusively to **FedRAMP-certified inference endpoints**: AWS GovCloud Amazon Bedrock (`F1603047866` — Portal26, Specset CUI mode, Silkline) or Azure Commercial Foundry OpenAI U.S. Data Zone Standard (`F1209051525` — Tarly Cowork).
  - **Non-Certified Inference / Tool TPIRs:** Where non-certified inference or search APIs are offered (Specset's Cloudflare Workers AI / Google AI Studio; Perplexity's Anthropic/Merge/Airbyte; Vbrick's GenAI flows), providers either **(i)** disable them completely in CUI / federal tenant modes, **(ii)** enforce contractual zero-data-retention / no-training controls + KMS encryption, and **(iii)** document all four `MAS-CSO-TPR` dimensions (usage, justification, mitigation, compensating controls).
  - **Developer / Internal Agents as TPIRs:** Specset (`FR2631258135`) explicitly lists laptop-based engineering coding assistants as **in-scope non-certified TPIRs** under `MAS-CSO-TPR` because they read CSO source code and documentation—directly validating the `internal-devsecops` agent profile in `fedramp-agent`!
  - **Observability TPIRs:** Certified government observability (`FR2023864279A` Datadog for Government, Dynatrace Class D, New Relic Class D) or **self-hosted in-boundary LLM tracing** (TrustGuard AI's in-partition GovCloud Langfuse) dominate over commercial SaaS trace collectors.

### (c) Prompt & Response Redaction from Telemetry
- **Observed Data:** Three distinct empirical controls appear across live Marketplace CPOs:
  1. **Zero-Content Telemetry Policy (`FR2631054533` Portal26):** Push operational/audit telemetry to Datadog for Government with *"no prompt or response content."*
  2. **Pre-Emission Redaction Enricher (`FR2628943632` Pryme Infil):** Application middleware strips personal fields and record content before log lines are written, emitting only tenant/user/request IDs, resource names, counts, and error codes.
  3. **Metrics-Only Bounded OTLP Opt-In (`FR2633058240` Ultra Security):** External eval telemetry exports metrics-only spans over a bounded OTLP exporter that is disabled by default.
- **Inference for `fedramp-agent`:** Prompt/response payloads are `FRD-FCD` (*Federal Customer Data*). Leaking them into observability logs silently converts an out-of-scope telemetry pipeline into an in-scope `MAS-CSO-IIR` / `MAS-CSO-MDI` / `CTL.SA.SA-09-05` violation and risks a `FRD-FRI` (*FedRAMP Reportable Incident*). Every `runtime-cso` agent MUST implement deterministic pre-log PII/prompt redaction and keep full LLM trace inspection inside the certified boundary (e.g., self-hosted in-boundary collector or Class C/D certified observability TPIR).

### (d) `includedInMinimumAssessmentScope` vs. `servicesOutsideMinimumAssessmentScope`
- **Observed Data:** Only `2 / 795` packages (`FR2628650874` Tarly Cowork and `FR2315464863` Palantir PFCS-SS) currently populate `servicesOutsideMinimumAssessmentScope`, and `10 / 795` populate per-service `includedInMinimumAssessmentScope` flags (`FR2628650874`, `FR2631054484`, `FR2315464863`, etc.). Both Tarly and Palantir explicitly exclude separately installed agency-hosted software and unconnected corporate/public products per OMB M-24-15 and `MAS-CSO-IIR` notes, while explicitly keeping **CI/CD delivery, staging verification, and evidence-publishing pipelines inside MAS**.
- **Inference for `fedramp-agent`:** In `agent-manifest.json`, `fedramp.in_minimum_assessment_scope` MUST default to `true` for any `runtime-cso` agent handling `FRD-FCD` or in-scope metadata (`MAS-CSO-MDI`) AND for any `internal-devsecops` agent that builds, signs, deploys, administers, or publishes compliance evidence for production. Standalone commercial/experimental agents must be explicitly segregated under `MAS-CSO-SUP` / `servicesOutsideMinimumAssessmentScope` with technical network/IAM barriers proving zero production or `FRD-FCD` access.

### (e) Digital Identity Readiness (`IAL2/AAL2` vs. `IAL3/AAL3`)
- **Observed Data:** Only `16 / 795` packages populate `digitalIdentityLevel` today:
  - **IAL2 / AAL2 / FAL2 (`10` packages, Class C pattern):** e.g., TrustGuard AI (`FR2633053629` — FIDO2/WebAuthn via AWS IAM Identity Center for privileged operators, signed SAML/TOTP for agency users), Partos (`FR2628647241`), SunStone (`XX-XXXXXXXX`), GitHub GHEC-US (`GitHub GHEC-US`).

### (f) SCN & IEC Notification Channels
- **Observed Data:** While `794 / 795` Marketplace JSON exports have not yet adopted structured top-level `changeNotificationMechanism` and `incidentNotificationMechanism` objects, Tarly Cowork (`FR2628650874`) demonstrates the complete CR-26 reference pattern:
  - **SCN (`changeNotificationMechanism`):** Single controlled certification-data distribution channel serving both a browser-readable gated notices page and machine-readable JSON (`SCN-CSO-HRM`, `SCN-CSO-NOM`).
  - **IEC (`incidentNotificationMechanism`):** Tri-channel delivery for Initial (`IIR`), Ongoing (`OIR`), and Final (`FIR`) Incident Reports to `fedramp_security@fedramp.gov`, verified agency-specific procedures, and the controlled certification-data distribution channel (`IEC-CSO-IIR`/`OIR`/`FIR`, `IEC-CSO-AIR`).
- **Inference for `fedramp-agent`:** Enterprise CSOs adopting `fedramp-agent` should emit machine-readable SCN records (`schemas/scn-record.schema.json`) and IEC incident runbook triggers (`templates/IEC-incident-runbook.md`) directly to their Trust Center API and `fedramp_security@fedramp.gov` pipeline, closing the 99.9% structured-metadata adoption gap observed across today's Marketplace corpus.
